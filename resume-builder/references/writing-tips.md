# 简历写作建议

面向应届/新人常见问题的最短版指南。核心：**具体、量化、动词开头**。

## Bullet 三要素：动作 + 结果 + 度量

不推荐：
> - 参与了 XX 系统的开发，负责前端相关工作，学习了很多东西

推荐：
> - **主导** XX 表单引擎重构，将 30+ 场景 schema 化，前端代码行数 **下降 45%**
> - **引入** 运行时校验框架，将线上表单类问题 **减少 60%**

模板：
```
[动词开头] [做了什么] [涉及范围/规模] [造成的量化结果]
```

**动词库**：主导 / 独立完成 / 设计 / 落地 / 推动 / 优化 / 沉淀 / 复现 / 分析 / 支持

## 没有数字怎么办

优先找这几类量化：
- 规模：条数、场景数、用户数、代码行数
- 时间：从 X 小时缩短到 Y 分钟
- 质量：bug 数下降、覆盖率提升、可用性 SLO
- 对外影响：文档阅读量、star 数、复用团队数

真的没有时，用相对量化（"占团队核心模块 3/8"）或直接说事实（"作为 Owner 沉淀了 4 篇技术方案"），比空口"很好地完成"更可信。

## 简历字段的取舍

- **不要**：政治面貌、身高体重、婚姻状况、身份证号、家庭地址、家庭成员详情
- **可以有**：城市偏好、性别（可选）、期望岗位（放在 `basics.label`）
- **加分**：GitHub / 技术博客 / 作品集链接（放到 `basics.profiles`）
- **学生特色**：GPA（≥3.5/4.0 或 85+/100 建议写）、排名（前 20% 建议写）、核心课程（≤6 门）

## 长度控制

- 应届/新人：**1 页**为宜，字号不小于 10pt
- 有 3+ 段工作经历：可 2 页，但同一段经历不要跨页
- 每段经历的 `highlights` 建议 **3-5 条**，超过 6 条会显得冗长

## 顺序建议

一般：**基础 → 教育 → 实习/工作 → 项目 → 技能 → 获奖 → 其他**

若你的强项是项目而非公司背景（如独立开发者、开源作者），把 `projects` 提到 `work` 之前。可以通过在 `resume.yaml` 里字段顺序 + 自定义主题实现。

## 中英双语

短期最简单方式：**同一份 yaml，`language: zh`；如需英文版单独维护 `resume-en.yaml`**。避免在同一份文件里塞中英对照，模板复杂度会飙升。
