# 用户画像收集指南

`profile.yaml` 是 career-planner 的核心数据文件。收集时的原则：**先粗后细，边聊边补**，不要一次性甩 20 个问题让用户回答。

## 分阶段收集

### 第一轮（必须）—— 30 秒能答完

- 姓名 / 年龄 / 城市
- 当前身份：**在校学生**（大几）/ **应届毕业生** / **工作 N 年**
- 专业 + 学校层级（985/211/双一流/普通本科/专科）

有这些就足以启动路径判断，不要在第一轮里问 GPA、实习经历等细节。

### 第二轮（引导用户展开）—— 根据第一轮定向

**分支 A：在校 / 应届 / 未明确方向**
- 最感兴趣的 3 门课程
- 最近 1 年做过最"来劲"的一件事（不管是不是学业）
- 家人 / 自己对"稳定 vs 挑战"的偏好

**分支 B：已有初步目标**
- 现在最纠结的选项（例：考研 vs 就业 / 大厂 vs 央企 / 国内 vs 出国）
- 3 年后希望自己在哪里、做什么

### 第三轮（简版测评）

引导做 Holland 60 题（见 `assets/assessments/holland-riasec.yaml`）。别一次抛 60 题，可以分 3 组每组 20 题。

### 第四轮（简历基线）

在有明确方向后再补齐：GPA、排名、实习、项目、语言分数、获奖……这些同时也是 `resume-builder` 的输入。

## 反模式

- **一次问太多**：用户会疲劳，且答得敷衍
- **过早追问细节**：还没确定方向就问"你的 GPA"意义不大
- **给固定选项**：路径选项应根据用户画像动态生成，而不是列 5 条让用户勾
- **忽略约束**：家庭经济、地域限制、健康状况都可能是硬约束，需要主动询问

## 输出

把每轮结果直接写到 `profile.yaml`（覆盖式增量更新即可），保证下次会话能续跑。
