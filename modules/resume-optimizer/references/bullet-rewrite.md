# Bullet 量化改写规则

## 诊断分类

对每条 highlight 进行模式匹配，识别以下问题类型：

### 问题类型一览

| 代码 | 类型 | 特征 | 示例 |
|------|------|------|------|
| VAGUE | 模糊描述 | 使用"相关""有关""一些"等模糊词 | "负责相关前端开发工作" |
| NO_VERB | 缺乏动词 | 以名词/形容词开头，没有行为主体 | "XX系统前端部分" |
| NO_RESULT | 无结果 | 只描述过程不提结果/影响 | "参与了用户增长项目的开发" |
| NO_QUANT | 无量化 | 有动作有结果但全是定性描述 | "大幅提升了页面性能" |
| DUTY_LIST | 职责罗列 | 复制 JD 式描述，只说"负责"不说"做成了什么" | "负责日常需求开发和 bug 修复" |
| TOO_LONG | 过长 | 单条超过 60 字，信息密度低 | （超长拖沓描述） |
| TOO_SHORT | 过短 | 单条少于 10 字，信息量不足 | "写了文档" |

### 检测模式（正则 + 语义）

```
VAGUE:     /相关|有关|一些|等等|各种|若干|很多|大量/
NO_VERB:   首字符不是动词（参考动词库）
NO_RESULT: 不含结果类关键词（提升|降低|减少|增加|优化|缩短|覆盖|达到|实现）
NO_QUANT:  不含数字 \d 且不含量化词（%|倍|次|个|条|行|人|天|小时|毫秒）
DUTY_LIST: /^负责|^承担|^完成日常/
TOO_LONG:  len > 60
TOO_SHORT: len < 10
```

## 改写公式

```
[强动词] + [做了什么（具体范围）] + [量化规模/复杂度] + [产出的量化结果]
```

### 强动词库（中文）

| 场景 | 推荐动词 |
|------|----------|
| 从 0 到 1 | 主导、设计、搭建、构建、创建 |
| 优化改进 | 重构、优化、迁移、升级、治理 |
| 日常迭代 | 开发、实现、落地、交付、支撑 |
| 数据分析 | 挖掘、分析、建模、验证、度量 |
| 团队协作 | 推动、对齐、沉淀、输出、牵头 |
| 工具/基建 | 沉淀、封装、抽象、复用、提效 |

### 量化数据追问策略

当用户 bullet 缺乏数据时，按以下优先级追问：

1. **规模指标**：涉及多少用户/场景/模块/接口？
2. **效果指标**：性能提升多少？错误率降低多少？耗时缩短多少？
3. **效率指标**：开发效率提升？人力节省？流程缩短？
4. **相对指标**：占团队产出比重？在多少候选方案中选中？

如果用户确实无法给出精确数字，可用：
- 量级估算："百万级 DAU""10+ 微服务"
- 相对表达："团队核心模块 3/8""全组唯一"
- 事实陈述："作为 Owner 独立完成""产出 4 篇技术方案被团队采纳"

## 输出规范

- 每条改写给出 `原文 → 改写` 对照
- 改写中的不确定数据用 `[?]` 占位，明确告知用户需要补充
- 一次最多展示 10 条，超过时分批（先改问题最严重的）
- 改写后的 bullet 长度控制在 25-55 字
